# 生物谷资讯长期抓取方案总览

## 目标理解
- 基于当前 `crawl4ai` Docker 服务，为 `https://www.bioon.com/` 首页“最新资讯”提供长期可复用抓取能力。
- 以结构化文件为主输出，手动触发为主、容器内定时触发为辅。
- 所有过程文档、操作说明、后续使用方法统一记录在当前目录 `操作方法记录/`。

## 改动范围
- Docker 服务新增业务化接口，供手动调用。
- 新增统一抓取内核，负责列表抓取、详情抓取、字段标准化、去重与结果落盘。
- 新增容器内定时触发脚本，定时调用同一 API。
- 新增 MySQL 存储层，作为结果、站点配置、调度配置和任务日志的主存储。
- 新增结果目录与状态文件说明文档。

## 实施思路
1. 把抓取逻辑封装成独立模块，避免散落在 `server.py` 中。
2. 提供 `/custom/bioon-news/run`、`/custom/bioon-news/status`、`/custom/bioon-news/latest` 等业务接口。
3. 结果写入 `runtime/bioon_news/`，按 `latest/`、`archive/`、`state/` 拆分。
4. 去重以 `url` 为主键，辅以 `title + publish_time` 指纹。
5. 手动与定时统一调用同一入口，避免两套逻辑分叉。
6. 页面选择器、默认分类、请求超时等可变规则集中放在 `deploy/docker/bioon_news_rules.json`，后续优先改规则文件，不直接改解析代码。
7. 当前主存储已升级为 MySQL；本地 JSON 仅作为调试输出和兼容性快照。

## 风险点
- 生物谷页面 DOM 变化会影响字段提取，需要把选择器集中管理。
- 规则文件改动后需要重启容器内服务进程，才能让新规则生效。
- `TAGS`、细分类、阅读数等字段首版不承诺完全稳定，优先保障核心字段。
- 容器内定时能力要尽量轻量，避免破坏现有 `supervisord + gunicorn` 运行形态。

## 验证方式
- 手动调用 API，确认可生成 `latest/news_latest.json`。
- 连续重复执行两次，确认无重复数据。
- 人工核对核心字段：`TITLE`、`URL`、`PUBLISH_TIME`、`DESC_ABS`、`CONTENT`。
- 模拟单篇详情失败，确认 `run_state.json` 中有错误记录。
