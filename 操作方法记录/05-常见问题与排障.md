# 常见问题与排障

## 问题 1：接口能通，但 `new_count=0`
### 可能原因
- 首页当前没有新增文章
- 去重状态中已经记录过这些 URL

### 处理方式
1. 查看 `runtime/bioon_news/state/seen_urls.json`
2. 使用 `force_refresh=true` 再试一次

## 问题 2：`failed_count > 0`
### 可能原因
- 单篇详情页临时访问失败
- 页面结构变化导致字段提取异常

### 处理方式
1. 查看 `runtime/bioon_news/state/run_state.json`
2. 若开启了 `save_raw=true`，检查 `raw/` 中对应 HTML
3. 手动打开失败 URL 对照页面结构

## 问题 3：容器内定时没有执行
### 可能原因
- `BIOON_NEWS_SCHEDULER_ENABLED` 未开启
- Gunicorn 服务尚未就绪，调度请求失败

### 处理方式
1. 检查环境变量
2. 检查容器日志中是否有 `[bioon-news-scheduler]`
3. 先手动调用 `GET /health` 与 `POST /custom/bioon-news/run`

## 问题 4：结果目录没有生成
### 可能原因
- 抓取请求未真正执行成功
- 进程对目标目录没有写权限
- 当前结果已改为 MySQL 主存储，你只看本地目录可能会误判

### 处理方式
1. 查看 API 返回中的 `output_file`
2. 检查 `run_state.json`
3. 检查容器内工作目录及挂载卷权限
4. 优先检查 MySQL 中的 `crawler_article` 是否已有结果

## 问题 6：接口报数据库相关错误
### 可能原因
- `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_DATABASE` 配置错误
- 目标数据库未创建
- MySQL 用户没有建表或写入权限

### 处理方式
1. 检查 `.llm.env` 或容器环境变量
2. 确认目标数据库已创建
3. 重新启动服务，让建表逻辑重新执行

## 问题 5：字段缺失
### 说明
首版优先保障核心字段，并采用回退规则：
- 无摘要时回退首页摘要或 `meta description`
- 无来源时置空
- 无栏目时置为 `未知栏目`

### 优先排查位置
先看 `deploy/docker/bioon_news_rules.json` 是否仍然匹配当前页面结构；多数页面改版问题都应先改规则文件，而不是直接改 Python 代码。

## 问题 6：我改了规则文件，但抓取结果没变化
### 可能原因
- 容器内服务进程还在使用旧代码或旧规则
- `BIOON_NEWS_RULES_FILE` 指向了其他路径

### 处理方式
1. 确认当前使用的规则文件路径
2. 重启容器或容器内服务进程
3. 再次手动调用 `POST /custom/bioon-news/run` 验证

## 建议排障顺序
1. `GET /health`
2. `GET /custom/bioon-news/status`
3. 手动 `POST /custom/bioon-news/run`
4. 检查 `run_state.json`
5. 必要时开启 `save_raw=true` 复现问题
