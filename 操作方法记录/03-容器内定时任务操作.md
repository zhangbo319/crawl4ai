# 容器内定时任务操作

## 目标理解
定时任务是辅入口，不直接写死站点参数，而是周期扫描数据库中的调度配置，再请求本机站点执行 API。

## 脚本位置
- 调度脚本：`deploy/docker/bioon_news_scheduler.py`
- 进程托管：`deploy/docker/supervisord.conf`

## 默认行为
- 调度进程始终启动
- 默认开启自动抓取
- 默认每 `60` 秒扫描一次数据库调度表
- 真正的执行时间由 MySQL 中的 `cron_expr` 决定

## 建议环境变量
```bash
BIOON_NEWS_SCHEDULER_ENABLED=true
BIOON_NEWS_SCHEDULER_INTERVAL_SECONDS=60
```

## 推荐策略
- 手动触发为主：`BIOON_NEWS_SCHEDULER_ENABLED=false`
- 定时兜底为辅：把站点任务写入 `crawler_schedule`
- 如果站点很多，可适当调大扫描间隔

## 查看定时运行情况
容器日志中搜索：
```text
[bioon-news-scheduler] trigger success
[bioon-news-scheduler] trigger failed
```

## 风险点
- 调度脚本依赖本机 `11235` 服务可用，服务未就绪时会记录失败日志
- 若设置过短周期，会增加无效扫描和站点访问频率

## 验证方式
1. 开启 `BIOON_NEWS_SCHEDULER_ENABLED=true`
2. 默认就是每小时 1 次；如需联调，可临时调小到几分钟
3. 观察容器日志与 `run_state.json` 是否持续更新
4. 如果你改过 `deploy/docker/bioon_news_rules.json`，先重启容器，再观察下一次定时抓取是否按新规则执行
5. 如需确认是定时任务而不是手动触发，可查询 `crawler_job_log.trigger_type`，调度触发会写入 `scheduler`
