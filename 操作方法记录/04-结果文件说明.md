# 结果文件说明

## 目标理解
结果现在以 MySQL 为主存储，结构化 JSON 降级为调试输出与兼容性快照。

## 文件结构
- `runtime/bioon_news/latest/news_latest.json`
  当前目标日期截至最近一次执行为止的本地调试快照，不再是主存储。
- `runtime/bioon_news/archive/YYYY-MM-DD/news_*.json`
  每次归档快照，适合回溯和审计。
- `runtime/bioon_news/state/seen_urls.json`
  已抓取 URL 集合，用于增量去重。
- `runtime/bioon_news/state/run_state.json`
  最近一次运行状态、结果路径和错误摘要。
- `runtime/bioon_news/raw/*.html`
  可选原始页面快照，仅在 `save_raw=true` 时生成。

## 每条新闻核心字段
- `title`
- `url`
- `publish_time`
- `desc_abs`
- `content`
- `logo`
- `resource`
- `primary_cls`
- `secondary_cls`
- `tags`
- `source_site`
- `crawl_time`
- `fingerprint`

## MySQL 主表
- `crawler_site`
- `crawler_schedule`
- `crawler_article`
- `crawler_job_log`

## 去重规则
- 主键：`url`
- 备用指纹：`url + title + publish_time` 计算的 `fingerprint`

## 最新结果的更新规则
- 首次抓取某天数据时，`latest/news_latest.json` 写入当天已抓到的全部文章
- 后续同一天的定时任务只抓新增文章，但会把新增结果合并回 `latest/news_latest.json`
- 因此 `latest` 始终代表“当天全集”，不是“本次新增”

## 风险点
- `tags` 首版可能为空
- `secondary_cls` 依赖页面标题后缀，页面结构变化时要跟进调整

## 验证方式
1. 检查 `latest/news_latest.json` 是否是合法 JSON
2. 检查 `seen_urls.json` 是否随着抓取逐步增加
3. 检查 `run_state.json` 中路径是否能直接定位到结果文件
